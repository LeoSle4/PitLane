# pitlane-ui-local
Objective: full app UI (all 56 HU) with local in-memory functionality, MVVM + Repository, ready to swap local repositories for Firebase ones.
Branch: none (user forbids any git command; a bash script with branch/commits/PR is delivered at the end). Delivery: script. Test runner: `./gradlew :app:testDebugUnitTest`, build: `./gradlew :app:assembleDebug`.

## Specs
S1. "respeta la arquitectura planteada" → MVVM + Repository per `docs/04-arquitectura/diagrama-componentes.png`: View (Fragment + XML) → ViewModel (StateFlow) → `I*Repository` → Repository. Modules: Auth · Perfil · Cliente · Técnico · Vehículo · Solicitud · Orden · Avance · Notificación.
S2. "el diseno y el prototipo en figma se puede mejorar mucho mas, solo es una base, pero se debe cumplir todos los hu planteados, todos debene estar" → all 56 HU of `docs/02-requisitos/historias-de-usuario.md` (views V-T01..V-T07, V-01..V-49) with their acceptance criteria, rules RN-01..RN-13; design base `docs/03-diseno/guia-diseno-y-prototipo.md`, improved.
S3. "el desarrollo de ahora sera solo el diseno de la app, pero con funcionalidad en local, es tener ya la funcionalidad, y tener todo listo, para luego solo cambiar el codigo para que trabaje con firebase, lo que trato de decri es, diseno pero con funcionalidad con variables locales y momentaneas en su ejecucion" → local in-memory repositories behind interfaces; swap point is `Dependencias`.
S4. Elements to use, verbatim: "Etcorreo / Text / EditText / Button / TextView / Spinner / Checkbox / Radiogroup -> uso radio button / Toast.maketext / List view —— legacy / Etiquetas / Imagenes / Cuadro combinados / Casillas de verificación / Grupo de opcion".

"no haras ni un comando en git, al final me daras un script en bash, con el pr y sus respectivos commits, como creacion de rama para el desarrollo para tener un buen control de versiones" → no git commands at all; final `scripts/entrega_git.sh` with branch, conventional commits (no AI attribution), PR via `gh`.

## Conventions (all units MUST follow)
- Package `com.leosle.pitlane`. Layers: `modelo/`, `util/`, `repositorio/` (interfaces `I*Repository`), `repositorio/local/`, `viewmodel/`, `vista/comun/` (UI kit), `vista/acceso|perfil|cliente|jefe|tecnico/`.
- Identifiers (classes, functions, variables, properties, resource names) in Spanish. Android/Kotlin API names stay as they are. Comments/KDoc in Spanish, one per class/function/block, objective + how it works only.
- Layout files: `frag_*.xml` screen, `hoja_*.xml` bottom sheet (edit), `dlg_*.xml` dialog, `item_*.xml` list row. ViewBinding is enabled (`FragMisVehiculosBinding`).
- View id prefixes: `btn` Button, `etx`/`et` EditText (`etCorreo`), `txt` TextView/label, `img` ImageView, `spn` Spinner (combo), `chk` CheckBox, `rg` RadioGroup, `rb` RadioButton, `lv` ListView (legacy), `ll`/`cl`/`sv`/`mcv`/`fl` containers (LinearLayout, ConstraintLayout, ScrollView, MaterialCardView, FrameLayout), `sw` switch.
- Required widgets per spec S4: EditText (plain `EditText` + own `txtError…` label below, no TextInputLayout), Button, TextView, Spinner, CheckBox, RadioGroup/RadioButton, ImageView, ListView (legacy, via `AdaptadorLista`), `Toast.makeText` (via `FragmentoBase.mostrarMensaje`) for every confirmation/error message.
- String resources per unit file `res/values/cadenas_<unidad>.xml`, names prefixed by unit (`cli_`, `jc_`, `jo_`, `tec_`, `com_`, `acc_`, `per_`). Layout/drawable/id names unique per unit by their HU-oriented names.
- ViewModels: no-arg constructor, repository injected from `Dependencias`, operations take a Spanish callback `alTerminar: (Resultado<T>) -> Unit` (called on main thread), lists exposed as `StateFlow`.
- Navigation: `(requireActivity() as Navegador)`; role entry points `RutasCliente`, `RutasJefe`, `RutasTecnico` list the tabs.
- Design: tokens from guide (colors light/dark, Plus Jakarta Sans, Phosphor icons already in `res/drawable/ic_*.xml`, radii 14/20/28, buttons 52dp, touch 48dp, glass only on bottom/top bars and status card). Respect `Reducir movimiento`.

## Unit contracts (T5-T8; parent owns `Rutas*.kt`, kit, domain, shell, acceso, perfil)
Shared kit (already written, read it before coding): `vista/comun/` (`FragmentoVinculado`, `Navegador`, `DialogoModal`, `HojaBase`, `GestorFotos`, `VisorFoto`, `AdaptadorLista`, `poblar`, `Campos`, `Combos`, `Opciones`, `EstadosVisuales`, `BarraSuperior`, `EstadoVacio`, `Animaciones`, `Imagenes`), `viewmodel/*`, `modelo/*`, `util/*`, styles in `res/values/styles.xml`, layouts `include_barra_superior`, `include_estado_vacio`, `include_zona_fotos`, `include_cargando`, `hoja_encabezado`.
Resource name prefixes keep units disjoint: Cliente `cli_`, Jefe clientes/técnicos `jc_`, Jefe órdenes `jo_`, Técnico `tec_` (layouts `cli_frag_*.xml`, `cli_item_*.xml`, `cli_hoja_*.xml`; strings `cadenas_cli.xml`; drawables `cli_*.xml`; ids are free inside a layout). Each unit writes only inside its own Kotlin package and its own prefixed resources. Do not run git. Do not edit the kit, domain, `Rutas*.kt`, manifest, themes or shared styles; if the kit lacks something, build a private helper inside your own package.
Screen rules: tab root screens override `mostrarBarraInferior = true`, show a greeting/title header (no back button) and give their `ListView` bottom padding `@dimen/relleno_lista_con_barra` with `clipToPadding=false`; pushed screens use `include_barra_superior` with back button via `BarraSuperior.configurar(...)` and `navegador.volver()`. Edit = bottom sheet (`HojaBase` subclass with `hoja_encabezado`, fields prefilled, locked fields via `Campos.bloquear`, "Guardar cambios" disabled until something changes). Delete/cancel/annul/deactivate/state change = `DialogoModal.confirmar`/`conCampo` and a failure result shows `DialogoModal.error(contexto, mensaje)`. Every success shows `mostrarMensaje(...)` (Toast). Every list has an empty state (`include_estado_vacio` as `ListView.emptyView`). Field errors appear under the field on blur (`Campos.validarAlSalir`) and on submit. Validation rules: `util/Validador`. Use real `EditText`, `TextView`, `Button`, `Spinner`, `CheckBox`, `RadioGroup/RadioButton`, `ImageView`, legacy `ListView`, `Toast` wherever an HU needs them (spinner for choosing vehicle/técnico/cliente, checkboxes for síntomas and términos, radio group for combustible and tipo de avance).
Design: improve on the Figma base (cards `style="@style/Tarjeta"`, status chips via `EstadosVisuales`, state-colored side bars, Display greeting on home, generous 16dp margins, 52dp buttons, light/dark tokens only from `@color/*`, no hardcoded colors).
